# Как пользоваться скриптами базы знаний

В папке `tools/` два скрипта:

| Скрипт | Что делает |
|---|---|
| `tools/render-diagrams.sh` | Рендерит диаграммы Mermaid (`diagrams/*.mmd`) в PNG |
| `tools/md2confluence.py` | Конвертирует страницы Markdown в Confluence Wiki Markup (`_build/confluence/…`) |

Обычный порядок после правки страниц: **сначала диаграммы, потом конвертация.**

```bash
tools/render-diagrams.sh
python3 tools/md2confluence.py
```

---

## 1. Что нужно установить (один раз)

- **Python 3.9+.** Подходит системный `python3` macOS, сторонние пакеты не нужны.
- **Node.js** и Mermaid CLI. Ставится локально в `tools/`:

```bash
cd tools && npm install
```

После этого появится `tools/node_modules/.bin/mmdc`, его использует `render-diagrams.sh`. Первый запуск может скачать Chromium для Puppeteer, это нормально.

---

## 2. Диаграммы: `tools/render-diagrams.sh`

### Где лежат исходники

У каждого раздела есть папка `diagrams/` (например, `05-native/diagrams/`). Правила:

- одна диаграмма = один файл `.mmd`;
- имя файла: `<имя страницы>--<короткое имя>.mmd`, например `04-android-native-api--intent-resolve.mmd`. Префикс до `--` нужен конвертеру: по нему он понимает, к какой странице относится картинка;
- PNG создаётся рядом с исходником и называется так же: `04-android-native-api--intent-resolve.png`.

### Запуск

```bash
tools/render-diagrams.sh
```

Перерисовываются только новые `.mmd` и те, что изменились после своего PNG. Перерисовать всё (например, после смены `tools/mermaid-config.json`):

```bash
tools/render-diagrams.sh --all
```

Скрипт печатает `→ путь/к/файлу.mmd` для каждой перерисованной диаграммы. Если вывода нет, значит всё актуально.

Параметры рендера: тема и цвета из `tools/mermaid-config.json` (палитра в стиле Confluence), белый фон, масштаб ×2 для чёткости.

### Как сослаться на диаграмму со страницы

В тексте страницы — обычная Markdown-картинка отдельной строкой (её показывает GitHub):

```text
![Диаграмма «Как система находит исполнителя Intent»](diagrams/04-android-native-api--intent-resolve.png)
```

Конвертер превращает её в `!04-android-native-api--intent-resolve.png|border=1!`, то есть в картинку-вложение
страницы Confluence. Старый формат-заглушка `> 🖼️ … \`x.png\`` тоже поддерживается.

### Подсказки по Mermaid

- Перенос строки в подписи: `<br/>`.
- Кавычки внутри подписи: `#quot;`, иначе парсер Mermaid ломается.
- Если длинные подписи обрезаются или переносятся слишком рано, задайте ширину переноса первой строкой файла:
  `%%{init: {"flowchart": {"wrappingWidth": 300}}}%%`
- Проверить синтаксис быстро: запустить скрипт и посмотреть, нет ли ошибки `mmdc`. Ошибка останавливает скрипт (`set -e`), на ней видно имя файла.

## 3. Конвертация в Confluence: `tools/md2confluence.py`

### Запуск

Все готовые страницы:

```bash
python3 tools/md2confluence.py
```

Отдельные страницы (пути относительно корня репозитория или абсолютные):

```bash
python3 tools/md2confluence.py 05-native/04-android-native-api.md 05-native/_index.md
```

Если Confluence у вас знает язык подсветки `dart`, можно отключить подмену на `java`:

```bash
python3 tools/md2confluence.py --dart-lang dart
```

### Что попадает в сборку

- `README.md` из корня (только до раздела «## 🛠» — дальше часть для GitHub) и все `.md` в папках разделов `NN-*` (`01-…` … `06-…`), включая `_index.md`.
- **Пропускаются:**
  - заглушки ещё не написанных тем (страницы с пометкой «📝 Запланировано»). Если передать такую страницу явно в аргументах, она всё же сконвертируется;
  - всё вне папок разделов: `_private/`, `_prototypes/`, служебные файлы в корне (кроме `README.md`).

### Куда кладётся результат

```text
_build/confluence/<раздел>/<страница>.txt
_build/confluence/<раздел>/<страница>--<диаграмма>.png   ← копии PNG этой страницы
```

Например, `05-native/04-android-native-api.md` → `_build/confluence/05-native/04-android-native-api.txt` и рядом все `04-android-native-api--*.png`.

> ⚠️ PNG копируются из `diagrams/` такими, какие они есть. Поэтому сначала запускайте `render-diagrams.sh`, иначе в сборку попадёт старая картинка.

### Что меняет конвертер

| Markdown | Confluence |
|---|---|
| `# … ######` | `h1. … h6.` |
| Таблицы, списки (вложенность через 2 пробела) | Таблицы и списки wiki-разметки |
| ` ```dart ` и др. | `{code:language=…}` по таблице языков ниже |
| `> ℹ️ …` / `> ⚠️ …` / `> 💡 …` / `> ✍️ …` | `{info}` / `{warning}` / `{tip}` / `{note}` |
| `![подпись](diagrams/x.png)` отдельной строкой | `!x.png\|border=1!` |
| `<details><summary>…</summary>` | `{expand:…}` |
| `` `код` `` | `{{код}}`; `{ } [ ] ?` внутри пишутся HTML-кодами, иначе Confluence падает с ошибкой 500 |

Языки подсветки, которых нет в Confluence, подменяются:

| В Markdown | В Confluence |
|---|---|
| dart, kotlin, kts | java |
| swift, json | javascript |
| objc, c, c++ | cpp |
| gradle | groovy |
| podfile | ruby |
| plist, xml, html | xml |
| yml | yaml |
| sh, shell, zsh, console | bash |
| text, gitignore, protobuf, cmake | noformat |

## 4. Перенос страницы в Confluence

1. Откройте страницу в Confluence на редактирование (для новой темы сначала создайте страницу в нужном разделе).
2. Удалите старое содержимое: Cmd/Ctrl+A → Delete.
3. **Insert markup:** Cmd+Shift+D (macOS) / Ctrl+Shift+D (Windows), либо «+» → «Markup».
4. Выберите формат **Confluence Wiki**.
5. Откройте `_build/confluence/<раздел>/<страница>.txt`, скопируйте весь текст и вставьте в окно. Справа будет предпросмотр. Нажмите **Insert**.
6. **Картинки.** Перетащите PNG этой страницы из той же папки `_build/confluence/<раздел>/` в редактор или загрузите через «…» → «Вложения». Имена файлов менять нельзя: разметка `!имя.png!` ищет вложение по точному имени. Если картинка уже была вложена раньше и не менялась, загружать её повторно не нужно. Если изменилась, загрузите её с тем же именем: Confluence сохранит её как новую версию вложения.
7. Сохраните/опубликуйте страницу и пролистайте её: проверьте, что все картинки показались. Если на месте картинки серая заглушка с именем файла, значит это вложение не загружено.

> 💡 Ссылки между страницами базы знаний в Markdown относительные (`../03-flutter/…md`). В Confluence их нужно один раз перепривязать на реальные страницы, если ссылка ведёт внутрь базы.

## 5. Как проверить, что сборка актуальна

Если какой-то `.md` правили после последней конвертации, его `.txt` устарел. Быстрая проверка (выводит устаревшие файлы; пустой вывод — всё актуально):

```bash
for md in README.md [0-9][0-9]-*/*.md; do
  txt="_build/confluence/${md%.md}.txt"
  [ -f "$txt" ] && [ "$md" -nt "$txt" ] && echo "устарел: $txt"
done
```

Страниц-заглушек в `_build` нет, поэтому для них проверка ничего не выводит. Если вывод не пустой, просто перезапустите `python3 tools/md2confluence.py`.

То же для диаграмм: `tools/render-diagrams.sh` без флагов сам перерисует всё, что устарело.
